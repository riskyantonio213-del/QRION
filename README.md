# QRION — Corporate Website

Marketing site for **QRION**, an Indonesian education technology company that
provides an integrated digital ecosystem for schools, madrasahs, and pesantren.

Built as a real, runnable Next.js application — not a set of static mock-ups.

## Tech stack

| Concern | Choice |
| --- | --- |
| Framework | Next.js (App Router, TypeScript, server components by default) |
| Styling | Tailwind CSS v4 with a CSS-variable design token system |
| UI primitives | shadcn/ui-style components over Radix (button, card, badge, input, textarea, label, accordion, sheet) |
| Icons | lucide-react (+ hand-rolled brand icons for social links) |
| Animation | Framer Motion (scroll reveals, ecosystem diagram, floating cards) |
| Charts | Recharts, code-split and client-only |
| Forms | React Hook Form + Zod, with server actions |
| Fonts | `next/font` — Plus Jakarta Sans (display) + Inter (body) |

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
```

```bash
npm run build    # production build
npm start        # serve the production build
npm run lint     # ESLint (next/core-web-vitals + typescript)
npm run typecheck  # tsc --noEmit
```

Copy `.env.example` to `.env.local` and fill in what you have. **Nothing is
required** — the site runs without any environment variables.

## Design tokens

Every brand colour is a CSS variable in `src/app/globals.css` and is exposed to
Tailwind through `@theme inline`, so re-theming means editing one file:

`--brand` `--brand-dark` `--brand-cyan` `--brand-soft`, plus the semantic
`--background` `--foreground` `--primary` `--muted` `--border` `--ring` tokens
and `--radius`. Use utilities such as `bg-primary`, `text-brand-cyan`,
`border-border`, `bg-soft` — never hard-coded hex values in components.

## Content architecture

Copy lives in data files, not inside layout components:

- `src/data/products.ts` — the single source of truth for all five modules
  (slug, category, headline, features, workflow, benefits, roles, FAQ, preview
  mock data, accent classes). **Adding a product here creates `/produk/<slug>`,
  the navbar entry, the product grid card, and the sitemap entry automatically.**
- `src/data/home.ts` — homepage section copy and icon sets.
- `src/data/dashboard.ts` — mock dashboard/demo values, shaped like API responses.
- `src/data/faq.ts` — site-level FAQ.
- `src/config/site.ts` — navigation, footer columns, socials, contact channels.

## Forms & CRM integration

Both forms validate on the client (React Hook Form + Zod) **and** on the server
(Zod again inside the action) before anything is sent.

The integration point is `deliverSubmission()` in
`src/app/actions/form-actions.ts`. Set `QRION_CRM_WEBHOOK_URL` to have
submissions POSTed as:

```json
{ "source": "qrion-website", "kind": "demo", "receivedAt": "…", "payload": { … } }
```

Delivery outcomes are surfaced honestly to the visitor:

- `success` — the endpoint accepted the payload.
- `error` — validation or delivery failed.
- `not_configured` — **no endpoint configured yet.** The visitor sees an
  "Integrasi form belum aktif" notice instead of a fake success message. No
  personal data is written to logs.

## Placeholders to replace before launch

Nothing in this repository fabricates company facts. Replace these when the real
information exists:

1. **Contact details** — `src/config/site.ts` / env vars (email, WhatsApp,
   address). Placeholder values are labelled in the UI.
2. **Social accounts** — env vars; until set, icons render as disabled.
3. **Login URL** — `NEXT_PUBLIC_LOGIN_URL`; until set, "Masuk" is disabled.
4. **Client logos** — `public/logos/*.svg` are generic placeholder artwork
   rendered via `next/image` in `src/components/sections/logo-cloud.tsx`.
5. **Legal pages** — `/kebijakan-privasi` and `/syarat-ketentuan` are clearly
   labelled frameworks awaiting legal review.
6. **Company facts** — `/tentang` intentionally omits history, team, funding,
   awards, or client counts.
7. **Site URL** — `NEXT_PUBLIC_SITE_URL` (the `qrion.example.com` fallback is a
   reserved, non-routable placeholder domain).
8. **All dashboard/product preview numbers** are labelled "Contoh data".

## Accessibility

Semantic landmarks, a skip-to-content link, labelled form controls with
`aria-invalid`/`aria-describedby` and `role="alert"` errors, keyboard-accessible
navigation (the Products dropdown opens on focus as well as hover), a focus-
trapping mobile sheet with focus restoration, visible focus rings, and full
`prefers-reduced-motion` support in both CSS and Framer Motion.

## Performance

Server components by default; client components only for interactivity. Recharts
is loaded with `next/dynamic` (`ssr: false`) so it stays out of the initial
bundle. Product pages are statically generated. OG images are generated at build
time. Fonts are self-hosted through `next/font` with `display: swap`.
